# VEN SEO and launch

Approved launch domain: **https://www.venexecs.com/**. The GitHub Pages version remains a no-index preview. This work does not launch the domain, change DNS, submit applications or change HubSpot workflows.

## Source of truth

- `ven-hospitality-v13-3/index.html` is the approved 25-page authoring bundle. It is read, never regenerated by this build.
- `site.json` contains each page's clean URL, search title, description and breadcrumb label.
- `build.py` generates ordinary HTML pages with the approved page bodies, shared styles and scripts.
- `runtime.js` preserves old hash bookmarks and the page/query context needed by the existing interactions.
- `verify.py` checks the output and preservation of body text, headings, form controls, portraits and unrelated mockups.

Keep using the authoring bundle for Grok/content changes. Do not overwrite it with the generated homepage downloaded from the public preview. Add a metadata entry when adding a new page; the build fails rather than silently publishing a page without metadata.

## What is included

- Twenty-five unique titles and descriptions in the initial HTML, before JavaScript runs.
- A separate, ordinary URL for every page, with HTML navigation links and self-referencing canonical URLs.
- Open Graph and X/Twitter preview tags, with an actual public JPEG image and descriptive alt text.
- Organization, WebSite, WebPage and relevant breadcrumb JSON-LD. No invented reviews, ratings, author identities or rich-result promises.
- Sitemap and robots.txt generated for the selected publication mode.
- Shared, fingerprinted CSS/JavaScript and real asset URLs. Visitors no longer download the entire authoring bundle to read one page.
- Existing role, example, advisor-pagination and form query strings retained. Tracking parameters are excluded from canonicals.
- Apply Now continues to the platform application; Can we help? continues to the learn-more lead form. The HubSpot endpoint, fields and live mode are preserved.

The share card uses the supplied temporary VEN wordmark and the approved homepage headline on an ivory background, rendered from `brand/social-card.html` at 1200×630. The original wordmark bytes are retained in `brand/ven-wordmark.png`. The supplied **Ink app-icon option** is copied exactly and used provisionally for the browser icon; the brand kit says final branding and icon choice remain open. Replace these when final brand assets are approved. The visible header wordmark and advisor portraits are untouched.

## Preview: current GitHub Pages site

```sh
python tools/ven-seo/build.py --output /path/to/new-preview-output --mode preview
python tools/ven-seo/verify.py --output /path/to/new-preview-output
node tools/ven-seo/runtime.test.cjs
```

The deployment workflow always uses preview mode. Every VEN page carries `noindex,nofollow`, and its sitemap contains no URLs. The preview canonical and social URLs use the GitHub preview host, keeping the unlaunched domain separate.

The `robots.txt` file inside a GitHub project subdirectory is not the host's root robots.txt and cannot control all of `foundernexus.github.io`. Preview exclusion relies on the HTML robots meta tag. Crawlers must be allowed to fetch a page to observe `noindex`.

The rest of the repository's mockups are copied unchanged. Old `#/clean/...` links redirect in the browser to the corresponding real page, preserving intent, role, campaign parameters and section anchors. Those fragments are unavailable to an HTTP server, so this compatibility step must run in the browser.

## Prepare the launch artifact

```sh
python tools/ven-seo/build.py --output /path/to/new-ven-launch-output --mode production --standalone
python tools/ven-seo/verify.py --output /path/to/new-ven-launch-output --standalone
```

The output folder is the deployable site root. In this artifact, canonicals, social URLs and the 25-URL sitemap use `https://www.venexecs.com/`; pages allow indexing, and root `robots.txt` points to `/sitemap.xml`. Building this folder does not deploy it or change the preview. The build requires a new or empty output folder and never deletes existing files.

Do not upload the launch artifact into the GitHub preview. Preview mode and production mode intentionally have different indexing policies.

## Complete when the final domain is launched

1. Deploy the standalone artifact to the root of `https://www.venexecs.com/` using the chosen host. Enable its HTTPS certificate.
2. Configure permanent host redirects from HTTP and the non-www domain to `https://www.venexecs.com/`, preserving paths and query strings. This is a hosting/DNS task and is not performed by this repository.
3. Check representative pages, assets, canonical URLs, the root robots.txt, the sitemap and a missing URL's actual 404 response on the final host. Do not use a catch-all rewrite that returns the homepage with status 200 for missing pages.
4. Confirm the approved domain and page URLs with Tobias and run a controlled live lead-form test on that domain. No HubSpot workflow changes are made by this SEO build.
5. Verify a `venexecs.com` Domain property in Google Search Console through its ownership flow. Submit `https://www.venexecs.com/sitemap.xml` and inspect the home, role and advisor pages. No verification token is fabricated or included here.
6. Run Google's Rich Results Test and PageSpeed Insights on the final domain. Valid JSON-LD and a tested build do not prove Google indexing, rich-result eligibility, rankings or measured Core Web Vitals.

## Validation scope

The automated checks cover initial HTML metadata, one H1 per page, unique snippets, canonical/social/schema agreement, crawlable internal links, local assets, sitemap membership, preview noindex, launch indexing, unchanged body text and form controls, original portrait bytes, and all unrelated repository files. The navigation tests cover old bookmarks, ordinary links, team/role/campaign context, advisor pagination and external application links.

The three emitted script adaptations only read page/query context on the new URL structure and keep the configured advisor-page title. They are recorded in the build report; the source scripts inside the authoring bundle are unchanged.
